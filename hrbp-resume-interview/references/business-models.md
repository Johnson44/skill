# 公司运行逻辑与岗位价值

## 通用业务链路

将公司分析成以下链路：

`客户/用户 → 供给或流量 → 产品/交易/服务 → 收入来源 → 成本结构 → 利润与增长`

研究时至少回答：服务谁、解决什么问题、核心资产是什么、通过什么方式收费、增长依赖什么、主要成本和风险是什么。

## 常见互联网业务方向

| 业务方向 | 价值链 | 常见收入来源 | 关键指标 | 典型岗位杠杆 |
|---|---|---|---|---|
| 内容/广告/推荐 | 内容供给 → 用户消费 → 分发 → 商业化 | 广告、品牌投放、内容/会员服务 | DAU、时长、留存、eCPM、转化、ROI | 内容运营、推荐产品、广告产品、数据/算法、技术稳定性 |
| 电商/零售 | 商品/商家 → 流量 → 交易 → 履约 | 商品差价、佣金、广告、物流和服务费 | GMV、转化、客单、复购、履约成本、退款 | 商家运营、用户运营、电商产品、供应链、后端 |
| 本地生活 | 商户供给 → 用户需求 → 撮合/履约 | 佣金、配送、广告、会员和服务费 | 订单、履约率、客单、补贴、商户留存 | 商户运营、交易产品、配送/调度、增长运营 |
| 游戏/直播/会员内容 | 内容或互动 → 活跃 → 付费 | 会员、虚拟道具、游戏内购、直播分成 | DAU、付费率、ARPU、留存、内容供给 | 活动运营、商业化产品、内容生态、客户端/服务端 |
| 云/企业服务 | 企业需求 → 平台/工具 → 使用和交付 | 订阅、资源用量、API、项目和专业服务 | 客户采用、调用量、续费、毛利、交付周期 | 企业产品、解决方案、客户成功、平台技术、售前/交付 |
| AI 产品/平台 | 模型/数据/算力 → 场景 → 任务结果 | API/调用、订阅、企业方案、云资源和效率收益 | 调用量、成功率、留存、成本、客户采用 | AI 产品、数据/算法、评测、产品运营、基础设施 |
| 硬件/生态 | 硬件设备 → 用户规模 → 服务和生态 | 硬件销售、配件、服务、IoT 和生态收入 | 出货、激活、复购、毛利、生态渗透 | 硬件产品、供应链、渠道/用户运营、客户端、质量 |
| 支付/金融科技 | 交易或金融服务 → 风险控制 → 服务 | 支付/技术服务费、平台服务、利息或其他合规收入 | 交易额、活跃、成本、风险、损失率 | 风控产品、支付产品、数据/算法、运营、合规技术 |

表格用于建立面试认知，不替代目标公司的最新官方业务和财报资料。涉及收入数字、业务占比或战略变化时，重新实时检索官方来源。

## 公司运行逻辑卡

针对目标公司输出：

1. **客户与场景**：谁付费，谁使用，谁提供供给。
2. **核心资产**：流量、内容、商品、履约、数据、技术、生态或品牌。
3. **业务闭环**：用户如何进入、使用、转化、复购或续费。
4. **收入机制**：直接收费和间接变现分别是什么。
5. **成本与约束**：获客、补贴、履约、算力、研发、内容、合规或风险成本。
6. **岗位连接**：目标岗位影响哪个环节，改变什么指标，如何证明结果。

## 岗位价值表达

使用以下句式帮助候选人回答“岗位如何创收”：

> 这个岗位不一定直接负责收款，但会通过【岗位动作】影响【业务环节】，进而改善【指标】；在公司当前的【业务模式/阶段】下，这会带来【收入增长、成本降低、效率提升、风险降低或长期用户价值】。

不要把“创收”简化成销售额。对于技术、质量、平台、风控和基础设施岗位，应清楚说明支撑收入、降低成本或控制风险的机制。
